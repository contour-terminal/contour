Install#

Contour is packaged for most systems; pick yours below, or take a build from the release page.

Fedora Linux#

Use the official package.

sudo dnf install contour-terminal

Arch Linux#

Use the official package.

sudo pacman -S contour

Ubuntu Linux#

Download the .deb file for your Ubuntu version from the release page, then install it:

sudo dpkg -i ~/Downloads/contour-0.3.12.262-UBUNTU_VERSION-ARCH.deb

Flatpak#

Contour is available at the Flathub store.

AppImage#

Every release also carries contour-VERSION-x86_64.AppImage, a single file that bundles Qt 6.11 (which Debian and Ubuntu do not ship) and everything else Contour needs but the C library. Make it executable and run it:

chmod +x contour-VERSION-x86_64.AppImage
./contour-VERSION-x86_64.AppImage

It runs on distributions with a glibc at least as new as Ubuntu 24.04's. Without FUSE, run it with --appimage-extract-and-run.

Building the AppImage yourself

To build it yourself, on the oldest distribution you want it to run on, install the build dependencies (scripts/install-deps.sh), Qt 6.11 with the qtmultimedia, qtshadertools and qtspeech modules (for instance through aqtinstall), a C++23 compiler and scripts/install-rust-wasm.sh, then:

QT_ROOT_DIR=/path/to/Qt/6.11.1/gcc_64 CXX=g++-15 VERSION_STRING=dev ./scripts/build-appimage.sh

The script builds Contour, installs it into an AppDir and packs it with linuxdeploy and its Qt plugin, which scans the QML files for the modules to bundle. The result is contour-dev-x86_64.AppImage in the current directory.

The Qt-free contour-daemon package for machines without a display is described in Contour daemon on a server.

Homebrew#

brew install contour

Installers (Windows 10 or newer)#

Download Contour for Windows from the release page and double click the installer (an .msi file). There are two installers, and you need one of them:

Installer Installs for Default folder Needs
contour-<version>-win64.msi everyone on the computer C:\Program Files\Contour\ an administrator's approval
contour-<version>-win64-user.msi you only %LOCALAPPDATA%\Programs\Contour\ nothing

Pick the per-user installer when you cannot or do not want to elevate. Both add Contour to the Start menu and, unless you deselect their features in the installer, to your PATH and your desktop. There is also a contour-<version>-win64.zip that needs no installation at all: unpack it anywhere and run bin\contour.exe.

With the Windows Package Manager:

winget install --id contour-terminal.Contour --silent --scope machine
winget install --id contour-terminal.Contour --silent --scope user
Upgrades and running instances
  • The two installers are separate products. Both can be installed on one computer, and neither ever upgrades or removes the other. When a command name is found in both, the per-machine PATH comes first.
  • An installer upgrades in place. Run any later build over an earlier one, or over a release, without uninstalling first; an older build of the same release also installs over a newer one. An upgrade keeps the folder Contour is in, even a folder you chose; the one exception is an old release's folder with its version in the name (Contour Terminal Emulator 0.8), which moves to a folder named Contour once. Installations of Contour 0.6.1 and earlier have to be uninstalled first.
  • A running Contour is closed and opened again. Windows Installer closes the Contour window it finds running and starts it again, with the arguments it had, once the files are replaced. A window whose sessions run in its own process (daemon.mode: in_process, or the fallback when no daemon could be started) loses them. Sessions a daemon hosts keep running: the installer moves a daemon started by hand out of the way first, and does not end one. What it leaves is described in Installing a new Contour on Windows.
Unattended installation, installer properties and winget

Run an installer without a dialog from a command prompt or a deployment tool:

msiexec /i contour-<version>-win64.msi /qn /norestart /l*v contour-install.log

Three properties change what it installs. Give them on the command line after the file name (INSTALL_ROOT is older than the other two):

Property Default Effect
INSTALL_ROOT=<folder> the installer's default folder (table above); on an upgrade, the folder Contour is in where Contour goes. A folder given here wins over the installed one, which moves the installation.
ADD_TO_PATH=0 1 does not add Contour's bin folder to PATH
DESKTOP_SHORTCUT=0 1 does not put a shortcut on the desktop

On an upgrade, ADD_TO_PATH=0 and DESKTOP_SHORTCUT=0 remove the entry or the shortcut the earlier installation made, and a later install with the default does not bring it back: name the feature again with ADDLOCAL=CM_C_contour_path (the PATH entry) or ADDLOCAL=ContourDesktopShortcutFeature (the shortcut).

msiexec reports through its exit code: 0 success; 3010 success, but a restart is needed; 1602 the installation was cancelled; 1603 a fatal error (also what an installer says when a later version of Contour is already installed: "A later version of Contour is already installed"); 1618 another installation is already running; 1638 another build of the same product is already installed with the same product code: this happens only between builds made before Contour 0.9, which all builds of one release shared; uninstall it first. Builds of 0.9 and later each have a product code of their own, and upgrade each other. The log named by /l*v has the detail.

With winget (commands above):

--scope machine installs the per-machine installer, --scope user the per-user one. Without --scope, winget prefers the per-user installer unless your winget settings say otherwise (installBehavior.preferences.scope): a plain winget install contour-terminal.Contour needs no administrator and installs into your profile. Name --scope machine for an installation for every user. winget upgrade keeps the scope Contour was installed in. The portable package (the ZIP, without installer) is available as winget install --id contour-terminal.Contour --installer-type portable, and winget upgrade keeps an installation made that way portable. Installations of Contour 0.6.1 and earlier have to be uninstalled first, also when winget offers the upgrade.

Installing as SYSTEM

A deployment tool that installs as the SYSTEM account cannot reach your daemon. Contour is still installed, but a daemon that you started by hand keeps running from the old folder until it next restarts. Deployment tools pass --scope machine to winget install: without it winget prefers the per-user installer, which would install into the profile of the SYSTEM account. See Installing a new Contour on Windows.

Installing from source#

Contour is best installed from supported package managers, but you can build from source by following the instructions below.

UNIX-like systems (Linux, FreeBSD, macOS)#

Prerequisites#

./scripts/install-deps.sh

This script might ask you for the administrator password if a package dependency can be installed via the system package manager.

Compile#

You can use cmake presets to compile contour. The full list of available presets can be seen using cmake --list-presets. To compile release build for linux clang-release or gcc-release, or appleclang-release on macOS accordingly. gcc-release, msvc-release and macos-package build as the packages are built (link-time optimization, so a slower link) and clang-release stays the fast developer build; -DCONTOUR_PRODUCTION_BUILD=ON turns the packages' flags on anywhere (see release builds).

cmake --preset clang-release
cmake --build --preset clang-release

# Optionally, if you want to install from source
cmake --build --preset clang-release --target install

Please note, if you want to install into a system root, e.g. /usr/local, you may need to prefix the install command with sudo.

Also, ensure that the terminfo file is correctly resolved, as the terminfo library is very limited in locating the correct terminfo files (e.g. it does not search in /usr/local), you can symlink into ~/.terminfo however.

Windows 10 or newer#

Prerequisites#

For Windows, you must have Windows 10, 2018 Fall Creators Update, and Visual Studio 2019, installed. It will neither build nor run on any prior Windows OS, due to libterminal making use of ConPTY API.

  1. Set up vcpkg, preferably somewhere high up in the folder hierarchy, and add the folder to your PATH.
cd C:\
git clone https://github.com/Microsoft/vcpkg.git
.\vcpkg\bootstrap-vcpkg.bat
  1. Install Visual Studio Build Tools (make sure to select the CLI tools for C++, which you might need to do in the separate components tab).
  2. Install Qt6 (i.e. to C:\Qt)
  3. Open the developer version of Powershell.
  4. In the contour source folder execute .\scripts\install-deps.ps1. This step may take a very long time.

Compile#

In the developer version of Powershell:

# change paths accordingly if you installed QT and vcpkg to somewhere else
cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=C:\vcpkg\scripts\buildsystems\vcpkg.cmake -DCMAKE_PREFIX_PATH=C:\Qt\6.5.0\msvc2019_64\lib\cmake
cmake --build build/

# Optionally, if you want to install from source
cmake --build build/ --target install
