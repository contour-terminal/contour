# Phase 2 whole-diff review — findings to fix (all of them)

1. (Important) Host death during a copy-path memory read is reported as a guest trap, so the breaker never counts it. Instance.cpp:91-96 + RemoteBackend.cpp:316-323, :524-544: fetch() on a broken lane → markDead() → nullopt → RemoteInstance::memory() nullopt → GuestMemory::view → ExtensionError::Trapped. Scenario: helper answers CallResult for render honestly, then dies before the MemoryRead loadByteString issues (Instance.cpp:489) → _fault = Trapped, reportHostFault(Trapped) no-op; Runner counts a guest trap, rebuilds under the same admission epoch, respawning the helper; a helper always dying there respawns faultsBeforeDisable × panes times; user sees "trapped". Same for lowering/lifting views in update/load. Contradicts D21 + "one host death counts once per extension". Fix: IWasmInstance::memory returns std::expected<std::span<std::byte>, MemoryFailure> with `enum class MemoryFailure : uint8_t { OutOfBounds, HostCrashed }` (update WAMR, Wasmtime, Remote, FakeWasmBackend, contract helpers, all callers); GuestMemory::view maps HostCrashed → HostUnavailable; RegistryRemote test killing the host between CallResult and the read → HostUnavailable and breaker faultCount() == 1.
