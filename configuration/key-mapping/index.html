Key Mapping#

To customize key mappings, you need to configure input_mapping yaml entry

Defining input_mapping replaces the built-in bindings — it does not add to them

As soon as an input_mapping section is present in your contour.yml, Contour's built-in defaults (Ctrl+Shift+V, the Ctrl+Shift+P command palette, the tab shortcuts, …) are discarded, and only the entries you list are active. Writing an input_mapping section is a declaration that you are defining the full set of bindings.

The contour.yml that Contour generates on first run already contains every default binding written out in full, so editing that section keeps the defaults you did not touch. If you are writing a configuration by hand and want to keep the defaults, start from a generated one (contour generate config) and add your entries to the existing list.

The default chords added since your configuration was generated (see Default chords) reach it the same way, among them Ctrl+Shift+C, Ctrl+Shift+W, the pane chords and the macOS ⌘P, ⌘W and ⌃⌘ chords (full screen's ⌃⌘F too).

These are consulted only when your input_mapping does not claim the same key or button (for the triple-click, the same button and click count), so binding one of them yourself replaces it.

They are built in rather than listed as defaults for the reason given in the warning above: an input_mapping section replaces the built-in list wholesale, and the generated contour.yml writes every default into that section. A binding added to Contour after your configuration file was written would therefore be shadowed by your own file forever. Consulting these after yours is what lets a new binding still reach you, while anything you bind explicitly keeps winning.

Ctrl+Tab is taken from the application

Like Windows Terminal, GNOME Terminal and Konsole, Contour claims Ctrl+Tab for tab switching, so a terminal application that wants it (via the Kitty keyboard protocol) will not receive it. Bind it in your own input_mapping to give it back to the application.

Pane chords on GNOME#

GNOME Shell takes both pane chords before any window sees them: its default switch-to-workspace-* shortcuts are Ctrl+Alt+Arrow and its move-to-workspace-* shortcuts are Ctrl+Shift+Alt+Arrow. So on GNOME, focusing and swapping panes with the defaults never reaches Contour. Either free the chords in GNOME's Settings › Keyboard › Keyboard Shortcuts › Navigation, or give the pane commands chords of their own in input_mapping, for example on Alt+Arrow and Alt+Shift+Arrow:

input_mapping:
    - { mods: [Alt],          key: LeftArrow,  action: FocusPaneLeft }
    - { mods: [Alt],          key: RightArrow, action: FocusPaneRight }
    - { mods: [Alt],          key: UpArrow,    action: FocusPaneUp }
    - { mods: [Alt],          key: DownArrow,  action: FocusPaneDown }
    - { mods: [Alt, Shift],   key: LeftArrow,  action: SwapPaneLeft }
    - { mods: [Alt, Shift],   key: RightArrow, action: SwapPaneRight }
    - { mods: [Alt, Shift],   key: UpArrow,    action: SwapPaneUp }
    - { mods: [Alt, Shift],   key: DownArrow,  action: SwapPaneDown }

Alt+Arrow then no longer reaches the program in the pane, so a shell's word motion on Alt+Left/Right is gone. Alt+Shift+Arrow is the default resize chord: input_mapping is matched in the order it lists its rows, so change the mods of the ResizePane rows a generated configuration writes on [Alt, Shift], or remove them, for the swap rows to fire.

macOS defaults#

  • The menu bar provides ⌘Q (Quit) and ⌘, (Settings…), and ⌘H, ⌥⌘H and ⌘M; Contour binds none of them by default, so they never reach input_mapping. Ctrl+Shift+letter reaches the program in the terminal, and a ⌘ chord nothing is bound to is consumed rather than typed as its letter.
  • ⌘K clears to the prompt (ClearToPrompt) on the primary screen; in the alternate screen it is consumed, so a running vim or tmux is never reset. ClearHistoryAndReset has no macOS default.
  • Font size is on ⌘0, ⌘- and ⌘+ only; Ctrl+0 reaches the program.
  • ⌘X and ⌘S are deliberately unbound (a terminal cannot cut, and there is nothing to save).
  • The defaults that hang on Ctrl+Alt plus a character answer to ⌃⌘ on macOS instead, because Option composes characters there (see below).
  • ⌥← / ⌥→ move by word (ESC b / ESC f) outside the alternate screen, and ⌘← / ⌘→ / ⌘⌫ edit the line, so these shell conventions work out of the box. Inside the alternate screen ⌥← reaches the program as the Alt+Left it is (CSI 1;3D).

Option as Alt#

Option has two jobs on a Mac: composing characters (⌥E then E gives é) and acting as Alt. The profile setting option_as_alt chooses which Option keys are Alt: off, left, right or both (true and false are still read as both and off). One rule applies everywhere:

  • An Option key that option_as_alt names is Alt, for every key: ⌥B sends ESC b, and an Alt+B binding fires.
  • An Option key it does not name composes on any key that has a composed character (⌥E, ⌥1 gives ¡) and is Alt only on keys that type nothing (arrows, Return, Backspace, the function keys), so ⌥← and Option+Enter keep working with option_as_alt: off.

Because of the second half, a binding of Alt plus a character cannot fire on an Option key that composes. Contour says so when it loads such a binding with option_as_alt set to off or to one side; bind the chord to Primary or Control instead, or name that side in option_as_alt.

Writing bindings#

Each element in the input_mapping represents one key binding, whereas mods represents an array of keyboard modifiers that must be pressed - as well as the key or mouse - in order to activate the corresponding action. Additionally one can filter input mappings based on special terminal modes using the mode option:

  • Alt : The terminal is currently in alternate screen buffer, otherwise it is in primary screen buffer.
  • AppCursor : The application key cursor mode is enabled (otherwise it's normal cursor mode).
  • AppKeypad : The application keypad mode is enabled (otherwise it's the numeric keypad mode).
  • Select : The terminal has currently an active grid cell selection (such as selected text).
  • Insert : The Insert input mode is active, that is the default and one way to test that the input mode is not in normal mode or any of the visual select modes.
  • Search : A search term is currently set. It outlives the find bar, so this stays true for as long as the matches are still highlighted; an open bar with nothing typed into it does not match.
  • Trace : The terminal is currently in trace-mode, i.e., each VT sequence can be interactively single-step executed using custom actions. See TraceEnter/TraceStep/TraceLeave actions.

Every condition separated by | must match. Prefix a condition with ~ to require that mode to be inactive. For example, Insert|Select requires both Insert mode and a terminal selection. Omit mode to match regardless of the active modes.

To make Ctrl+V paste from the clipboard in Insert mode, including at a prompt with no selection, use the following entry under input_mapping.

- { mods: [Control], key: V, action: PasteClipboard, mode: Insert }

key represents keys on your keyboard, and mouse represents buttons as well as the scroll wheel.

Modifiers, which are case-insensitive (Control, control and CONTROL are the same modifier):

  • Shift
  • Alt
  • Control — may also be written Ctrl
  • Super — may also be written Meta. This is the Windows key on Windows, the Command key on macOS, and the Super key on anything else.
  • Hyper

Note

Meta is a synonym for Super for historical reasons: contour.yml has spelled the Windows/Command key Meta since before a separate Meta modifier existed. There is currently no configuration spelling for the distinct Meta modifier that the extended CSI u keyboard protocol reports.

  • Primary — the chord an application's own commands hang on: Command (Super) on macOS, Control + Shift everywhere else. One row mods: [Primary], key: C, action: CopySelection is therefore Ctrl+Shift+C on Linux and Windows and ⌘C on macOS, and Contour's built-in defaults are written that way. Primary can be combined with further modifiers ([Primary, Shift]), and the generated contour.yml spells it Primary wherever a default row uses it, so one file works on every machine you share it between.

An entry naming a modifier that is not in this list is rejected as a whole — the binding is dropped rather than bound with a partial chord — and the reason is reported on startup.

Keys can be expressed case-insensitively symbolic:

APOSTROPHE, ADD, BACKSLASH, COMMA, DECIMAL, DIVIDE, EQUAL, LEFT_BRACKET, MINUS, MULTIPLY, PERIOD, RIGHT_BRACKET, SEMICOLON, SLASH, SUBTRACT, SPACE Enter, Backspace, Tab, Escape, F1, F2, F3, F4, F5, F6, F7, F8, F9, F10, F11, F12, DownArrow, LeftArrow, RightArrow, UpArrow, Insert, Delete, Home, End, PageUp, PageDown, Numpad_Divide, Numpad_Multiply, Numpad_Subtract, Numpad_Add, Numpad_Decimal, Numpad_Enter, Numpad_Equal, Numpad_0, Numpad_1, Numpad_2, Numpad_3, Numpad_4, Numpad_5, Numpad_6, Numpad_7, Numpad_8, Numpad_9

or in case of standard characters, just the character.

A single-character key also matches case-insensitively: key: 'q' and key: 'Q' bind the same chord. Shift is carried by mods, not by the letter's case, so writing an uppercase letter does not mean "with Shift" — use mods: [Shift] for that.

Mouse buttons can be one of the following self-explanatory ones:

Left, Middle, Right, WheelUp, WheelDown, WheelLeft, WheelRight

A mouse binding may also name a click count with clicks (1 to 4). Such a binding fires on that click of a multi-click sequence only, and it is consulted before Contour's own double-, triple- and quadruple-click selection, so it replaces that selection for the chord it names:

input_mapping:
    - { mods: [Control], mouse: Left, clicks: 3, action: SelectCommandBlock, target: pointer, part: output }

A binding without clicks fires on every press that no clicks binding claimed. Like the selection it replaces, a clicks binding never takes a click that an application asked for, unless the bypass_mouse_protocol_modifier is held.

clicks applies to the Left, Middle and Right buttons only: a wheel step is never more than a first click. An entry that gives it to a key or a wheel, or a count other than 1 to 4, is dropped and the reason is reported on startup.

Switching daemons and workspaces#

These actions re-point the window they fire in at another workspace or daemon (see Switching a window). Two of them are bound by default. CycleWorkspace is Ctrl+Alt+PageDown / PageUp (Linux, Windows) and ⌃⌘↓ / ⌃⌘↑ (macOS): it shows the next / previous workspace, one level up from the tab chords. MoveWorkspaceDown / MoveWorkspaceUp are the same chords with Shift: they move the current workspace down / up the list. The command palette lists them all under Daemons. They need a window that shows a daemon.

Action Key What it does
SwitchToWorkspace index: (1-based, required) Shows the Nth workspace of this window's daemon here.
NewWorkspace none Creates a workspace and shows it in this window; for a window attached to a daemon, the workspace is created on that daemon.
OpenWorkspace index: (1-based, required) Shows it in a new window.
CycleWorkspace direction: next\|previous (default next) Shows the next or previous workspace of this window's daemon here, hidden and left ones included, in their position order.
CycleDaemon direction: next\|previous (default next) Shows the next or previous daemon here: the local daemons running, by name, then the saved hosts a window here shows.
SwitchToDaemon name: or host: (exactly one) Shows the named local daemon, or saved host, here.
OpenDaemon name: or host: (exactly one) Shows it in a new window. 
input_mapping:
  - { mods: [Control, Alt], key: '2', action: SwitchToWorkspace, index: 2 }
  - { mods: [Control, Alt], key: PageDown, action: CycleWorkspace, direction: next }
  - { mods: [Control, Alt, Shift], key: RightArrow, action: CycleDaemon, direction: next }
  - { mods: [Control, Alt], key: A, action: SwitchToDaemon, name: admin }
  - { mods: [Control, Alt], key: H, action: OpenDaemon, host: home }

The cycling actions never wait on a daemon: they step through what was last looked up, and look again in the background for the next press, so the first press after a change (or right after start-up) may still see the earlier list.

A binding that gives no index (or 0), an unknown direction, or neither or both of name and host is dropped, and the reason is reported on startup. Until 0.9.0 a binding's label: still loads as name:, with a configuration warning naming the new key. Landing on a daemon with several workspaces opens the switcher popup on that daemon's workspaces, to pick one; Esc there cancels the switch and changes nothing.

Action What it does
ShowSwitcher Opens the daemon and workspace switcher popup over this window.
NewDaemon Asks for a name, starts a local daemon under it, and opens a new window on it.
UpgradeDaemon Upgrades this window's local daemon in place, keeping every program running (palette: Upgrade daemon).

The switcher popup lists the daemons under This computer (the local daemons running, by name) and Saved hosts. This window's daemon is expanded; Right expands any other one to its workspaces, each with its tab count and whether it is shown in this window, shown elsewhere, hidden or not shown, plus "+ new workspace on …". A saved host not connected yet says so, and is connected to when it is expanded or chosen. Typing filters the list, Return switches this window to the selected row, Shift+Return opens it in a new window, and Esc closes the popup without changing anything.

NewDaemon (also the popup's New daemon… row) refuses a name a socket cannot be named after (letters, digits, -, _ and . only, not starting with a dot, at most 64 characters) right under the field; a name that is already running is offered as "Switch to daemon …" instead of starting a second one. The daemon it starts keeps running when its last window closes, like one started with contour daemon --name.

UpgradeDaemon (the palette's Upgrade daemon row) starts a live upgrade of the window's daemon at any time, without the daemon-drift chip: it also upgrades a daemon that runs the same release, to pick up a rebuilt binary. It asks nothing, as an upgrade keeps every program running. It is for the local daemon this client launched on (one started with New daemon… is not); for a remote daemon, one a switch reached, a daemon too old to upgrade in place, or one newer than this client it does nothing but tell you why in a notice. It is not bound to a key by default.

SearchSelection Searches for the selected text: its first line becomes the find bar's pattern, escaped when the bar searches by regular expression.
SendChars Writes given characters in chars member to the applications input.
ToggleAllKeyMaps Disables/enables responding to all keybinds (this keybind will be preserved when disabling all others).
ToggleFullscreen Enables/disables full screen mode.
ToggleInputMethodHandling Enables/disables IME (input method editor) handling.
ToggleInputProtection Enables/disables terminal input protection.
ToggleMouseForwarding Blocks/forwards mouse events to applications that track the mouse, until a profile switch or a configuration reload re-imposes the profile's mouse_forwarding.
ToggleStatusLine Shows/hides the VT320 compatible Indicator status line.
ToggleTitleBar Shows/Hides titlebar
TraceBreakAtEmptyQueue Executes any pending VT sequence from the VT sequence buffer in trace mode, then waits.
TraceEnter Enables trace mode, suspending execution until explicitly requested to continue (See TraceLeave and TraceStep).
TraceLeave Disables trace mode. Any pending VT sequence will be flushed out and normal execution will be resumed.
TraceStep Executes a single VT sequence that is to be executed next.
ViNormalMode Enters/Leaves Vi-like normal mode. The cursor can then be moved via h/j/k/l movements in normal mode and text can be selected via v, yanked via y, and clipboard pasted via p.
WriteScreen Writes VT sequence in chars member to the screen (bypassing the application).
CreateNewTab Creates a new tab in the terminal emulator.
CloseTab Closes current tab.
MoveTabTo Moves current tab to the given position (starting at number 1).
MoveTabToLeft Moves current tab to the left.
MoveTabToRight Moves current tab to the right.
SwitchToTab Switch to absolute tab position (starting at number 1)
SwitchToPreviousTab Switch to the previously focused tab
SwitchToTabLeft Switch to tab to the left
SwitchToTabRight Switch to tab to the right
RenameTab Rename the current tab inline (opens the tab's name editor). Its old name SetTabTitle still loads until 0.9.0.
SplitVertical Splits the active pane into two side-by-side panes (a vertical divider).
SplitHorizontal Splits the active pane into two stacked panes (a horizontal divider).
ClosePane Closes the active pane (or the tab if it is the last pane).
FocusPaneLeft Moves pane focus to the left.
FocusPaneRight Moves pane focus to the right.
FocusPaneUp Moves pane focus up.
FocusPaneDown Moves pane focus down.
SwapPaneLeft Swaps the active pane with its left neighbor.
SwapPaneRight Swaps the active pane with its right neighbor.
SwapPaneUp Swaps the active pane with its upper neighbor.
SwapPaneDown Swaps the active pane with its lower neighbor.
MovePaneLeft Moves the active pane past its left neighbor.
MovePaneRight Moves the active pane past its right neighbor.
MovePaneUp Moves the active pane past its upper neighbor.
MovePaneDown Moves the active pane past its lower neighbor.
ToggleSplitOrientation Flips the orientation of the active pane's split (horizontal <-> vertical).
TogglePaneZoom Zooms the active pane so it alone fills the tab, hiding its siblings; toggles back to the tiled layout. While zoomed, moving pane focus keeps the zoom and shows the newly focused pane.
NewWorkspace Creates a workspace and shows it in this window; the one shown before keeps running, hidden. On a window attached to a daemon the daemon creates it; a window attached to a tmux server refuses.
ResizePane Grows or shrinks the active pane in the given direction (by an optional percent).
LaunchLayout Opens a named layout, appending its tabs to the current window.
SaveLayout Saves the current window's tabs as a named layout in layouts.yml. Without a name it opens a prompt to type one in (which is how the command palette offers it).
AttachToHost Opens a new window attached to the saved host name (see hosts:).
OpenContextMenu Opens the terminal pane's context menu. Bound to the right mouse button by default, and only fired when the running application has not asked for the mouse itself (hold Shift to open it anyway).
SelectAll Selects everything the terminal holds: the whole scrollback and the whole screen.
SoftReset Performs a terminal soft reset (DECSTR): resets modes, rendition and cursor state, while keeping the screen contents and the scrollback.
CopyLastCommandPrompt Copies the prompt line(s) of the most recently finished command into the clipboard. Requires a shell that emits OSC 133 marks (see Contour's shell integration).
CopyLastCommandOutput Copies what the most recently finished command printed into the clipboard. Requires a shell that emits OSC 133 marks (see Contour's shell integration).
CopyLastCommandBlock Copies both the prompt and the output of the most recently finished command into the clipboard. Requires a shell that emits OSC 133 marks (see Contour's shell integration).
CopyHyperlink Copies the URI of the hyperlink under the mouse cursor into the clipboard.
SetTabColor Colorize the current tab. Without a color, this opens the tab's color picker; with one (e.g. color: '#ff0000') it applies that color right away.
ResetTabColor Removes the color you gave the current tab, restoring its default look (or the color the running application assigned, if it assigned one).
CloseAllTabs Closes every tab in this window. With only one window open, that closes Contour.
SetTabBarVisibility Sets when this window's tab bar is shown (mode: always, never or multiple). Applies to this window until it is closed; the settings page is where the choice is made permanent.
SetTabBarPosition Places this window's tab bar above or below the terminal (position: top or bottom). Applies to this window until it is closed; the settings page is where the choice is made permanent.
SpeakSelection Reads the selected text aloud through the operating system's speech synthesizer. Available only where a speech engine and a voice are installed.
StopSpeaking Stops reading aloud.
SelectCommandBlock Selects one part of a command block as whole lines (target: pointer, cursor or last; part: output, input or all). Requires a shell that emits OSC 133 marks.
CopyCommandBlock Copies one part of a command block into the clipboard as plain text (target: pointer, cursor or last; part: output, input or all). Requires a shell that emits OSC 133 marks.
CopyCommandLine Copies the command line of a command block into the clipboard, with the control characters that would be unsafe to paste removed (target: pointer, cursor or last). Requires a shell that reports its command lines (OSC 133;C cmdline_url).
RerunCommand Runs the command line of a command block again: typed at the shell's prompt and entered, once the command it would run has been shown and confirmed (target: pointer, cursor or last). Requires a shell that marks its prompts (OSC 133) and reports or shows its command lines; refused while a command is running, and for a command line that cannot be typed as it is.
ToggleCommandFold Collapses or expands a command block's output (target: pointer, cursor or last). Requires a shell that emits OSC 133 marks, and folding to be enabled.
ClearToPrompt Clears the scrollback and the screen above the current prompt. A prompt on the screen moves to its top, with a running command's output; one in the scrollback becomes the oldest line kept. Requires a shell that emits OSC 133 marks.
OpenCommandOutput Opens a command's output in a pager (target: pointer, cursor or last; program: the pager, read as command_blocks.pager is, which it replaces when given; placement: split, tab or detached; format: sgr or plain, by default command_blocks.pager_format for the configured pager and sgr for a named program). Detached pipes plain text into the program's standard input instead of opening a pane, and is the one placement a daemon-attached session offers. Requires a shell that emits OSC 133 marks.
CloseOtherTabs Closes every tab in this window except the current one.
CloseTabsToRight Closes every tab to the right of the current one.
MoveTabToNewWindow Moves the current tab into a new window of its own. Does nothing with a single tab.
ShowAbout Shows the version of Contour.
MinimizeWindow Minimizes this window.
ZoomWindow Maximizes this window, or restores it when it is maximized (the macOS Zoom).
FocusNextArea Moves keyboard focus to the next area of the window: terminal, tabs, toolbar, and back.
FocusPreviousArea Moves keyboard focus to the previous area of the window: terminal, toolbar, tabs, and back.
FocusToolbar Moves keyboard focus to the window's toolbar.
ToggleSidebar Shows the workspace sidebar when it is hidden, and hides it when it is shown.
FocusSidebar Moves keyboard focus into the workspace sidebar, showing it first when it is hidden.
FilterWorkspaces Opens the workspace sidebar's filter with the keyboard in it, showing the sidebar first when it is hidden.
JumpToNextAttention Shows the next pane that needs you: one that waits for input, or whose command failed.
MarkSeen Marks the output of the active pane as seen.
RenameWorkspace Renames the current workspace inline.
MoveWorkspaceUp Moves the current workspace one place up in the sidebar's list.
MoveWorkspaceDown Moves the current workspace one place down in the sidebar's list.
CloseWorkspace Closes the current workspace and everything in it, after asking. The last workspace of a window that runs its sessions in-process cannot be closed.
SetWorkspaceColor Colorize the current workspace. Without a color, this opens the workspace's color picker; with one (e.g. color: '#c2548f') it applies that color right away.
ResetWorkspaceColor Removes the color you gave the current workspace, restoring its default look.
GoToPane Shows the pane a sidebar row names and focuses it.
MoveTabToWorkspace Moves the current tab into the workspace at the 1-based position index of this window's list.
MoveToTab Moves the current pane into another tab, as a split beside its active pane: the tab at the 1-based position tab of the workspace at the 1-based position workspace of this window's list.
MoveToNewTab Moves the current pane into a tab of its own, at the end of its workspace.
MoveToNewWorkspace Moves the current pane into a workspace of its own, named as a new workspace is.
SwitchToWorkspace Shows the workspace at the 1-based position index of this window's daemon in this window. Hidden workspaces are not counted. Does nothing for a window that runs its sessions in-process.
OpenWorkspace Shows the workspace at the 1-based position index of this window's daemon in a new window. Does nothing for a window that runs its sessions in-process.
CycleWorkspace Shows the next (direction: next, the default) or previous (direction: previous) workspace of this window's daemon in this window, wrapping around.
CycleDaemon Shows the next (direction: next, the default) or previous (direction: previous) daemon in this window: the local daemons by name, then the saved hosts some window shows; wrapping around.
SwitchToDaemon Shows the daemon named by name (a local daemon) or host (a saved host, see hosts:) in this window. A binding that names neither, or both, is dropped.
OpenDaemon Shows the daemon named by name (a local daemon) or host (a saved host, see hosts:) in a new window. A binding that names neither, or both, is dropped.
ShowSwitcher Opens the popup to switch this window to another daemon or workspace, or to open one in a new window.
NewDaemon Asks for a name, starts a new local daemon of that name and shows it in this window.
UpgradeDaemon Upgrades this window's local daemon in place, keeping every program running, even when the daemon already runs this release (to pick up a rebuilt binary). Refused for a remote daemon, or one this client did not start or launch on.
